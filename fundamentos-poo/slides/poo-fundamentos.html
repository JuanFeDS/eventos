¿Qué es la POO?

Una forma de organizar el código alrededor de "cosas" en vez de solo pasos

Concepto

Agrupas datos y comportamiento en un mismo lugar.

En vez de tener variables sueltas y funciones que las reciben una por una, defines un tipo propio que ya sabe qué datos tiene y qué puede hacer con ellos.

Analogía Piensa en una impresora 3D: no manejas cables y motores por separado — le mandas un archivo y ella sabe cómo moverse. Un objeto funciona igual: le pides algo y él sabe cómo hacerlo con sus propios datos.
01

Clases y objetos

El molde y lo que sale de él

Concepto

Una clase es un molde. Un objeto es una instancia de ese molde.

Defines la clase una sola vez. Cada objeto que creas a partir de ella tiene la misma estructura, pero sus propios valores.

Analogía Un molde de galletas es la clase. Cada galleta horneada es un objeto — misma forma, pero cada una es su propia galleta.

Código

Definir una clase e instanciarla

__init__ se ejecuta automáticamente cada vez que creas un objeto nuevo.

persona.py
class Persona:
    def __init__(self, nombre, edad):
        self.nombre = nombre
        self.edad = edad

ana = Persona("Ana", 28)
print(ana.nombre, ana.edad)
Ana 28
02

Atributos, métodos y self

Los datos de un objeto y lo que puede hacer con ellos

Concepto

Los atributos guardan datos. Los métodos definen comportamiento.

self es cómo un método se refiere "a este objeto en particular" — es lo que le permite usar los datos propios de cada instancia.

Analogía Si dos personas llenan el mismo formulario, cada una llena sus propios campos. self es la forma en que el método sabe de cuál formulario está hablando.

Código

Un método que usa los atributos del objeto

Cada objeto responde con su propio nombre, porque cada uno tiene su propio self.

persona.py
class Persona:
    def __init__(self, nombre, edad):
        self.nombre = nombre
        self.edad = edad

    def saludar(self):
        print(f"Hola, soy {self.nombre}")

ana = Persona("Ana", 28)
ana.saludar()
Hola, soy Ana
03

Encapsulamiento

Proteger los datos internos de un objeto

Concepto

No todo lo que tiene un objeto debería poder cambiarse desde afuera.

En Python, el prefijo _ es la convención para "esto es interno, no lo toques directamente" — y @property te deja exponer un valor de forma controlada.

Analogía Un cajero automático no te deja meter la mano a la bóveda — usas botones (métodos) que validan la operación antes de tocar el dinero de verdad.

Código

Un saldo que solo cambia por un método controlado

_saldo no se edita directo — pasa siempre por depositar(), que puede validar antes de modificarlo.

cuenta.py
class CuentaBancaria:
    def __init__(self, saldo_inicial):
        self._saldo = saldo_inicial

    def depositar(self, monto):
        if monto > 0:
            self._saldo += monto

cuenta = CuentaBancaria(100)
cuenta.depositar(50)
print(cuenta._saldo)
150
04

Herencia

Reutilizar una clase en vez de repetirla

Concepto

Una clase hija hereda de una clase padre

Animal
↓
Perro
Gato

Código

Perro hereda todo lo de Animal

No repites __init__ — Perro ya lo tiene, solo agrega lo que le falta.

animales.py
class Animal:
    def __init__(self, nombre):
        self.nombre = nombre

class Perro(Animal):
    def hacer_sonido(self):
        return "Guau"

firulais = Perro("Firulais")
print(firulais.nombre, firulais.hacer_sonido())
Firulais Guau
05

Polimorfismo

Mismo método, comportamiento distinto

Concepto

Puedes tratar objetos distintos de forma idéntica.

Si Perro y Gato heredan de Animal y ambos definen hacer_sonido(), puedes llamar ese método sin importarte de qué clase es cada uno.

Analogía Aprietas "play" en cualquier reproductor — un CD, un celular, una app — y cada uno sabe cómo reproducir a su manera. Tú solo apretaste el mismo botón.

Código

Un mismo bucle, dos comportamientos

El código no pregunta qué clase es cada animal — solo llama hacer_sonido().

animales.py
class Gato(Animal):
    def hacer_sonido(self):
        return "Miau"

for animal in [Perro("Firulais"), Gato("Michi")]:
    print(animal.hacer_sonido())
Guau Miau

Para recordar

Si dos clases repiten código, probablemente falta una clase padre.
