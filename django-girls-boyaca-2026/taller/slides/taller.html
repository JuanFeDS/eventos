¿Qué es Django?

El framework que vas a usar hoy

Antes de instalar nada

Django es un framework de Python para hacer sitios web rápido.

Te da piezas ya armadas — manejo de base de datos, panel de administración, seguridad — para que no tengas que reinventarlas desde cero. Lo usan sitios tan grandes como Instagram, Mozilla y Pinterest.

Importante

No vas a escribir todo desde cero.

Gran parte de lo aburrido y repetitivo ya viene resuelto. Tu trabajo hoy es conectar las piezas y entender cómo funcionan juntas.

02

Instalación de Django

Esta vez, dentro de tu proyecto

¿Por qué un entorno virtual?

Aísla las herramientas de este proyecto del resto de tu computador.

Así, lo que instalas hoy para tu blog no choca con nada más que tengas instalado — ni con lo que instalen tus compañeras en sus equipos.

Paso a paso

Crea y activa tu entorno virtual

  1. 1

    Abre la terminal dentro de la carpeta de tu proyecto.

  2. 2

    Crea el entorno: python -m venv myvenv

  3. 3

    Actívalo: . myvenv\Scripts\activate.ps1

  4. 4

    Vas a ver (myvenv) al inicio de tu línea — así sabes que quedó activo.

Captura pendiente
(entorno virtual activado)

Si ves un error

"La ejecución de scripts está deshabilitada"

Ya resolviste esto en el prework con Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned. Si te vuelve a salir, es porque no se guardó — corre ese mismo comando otra vez.

Paso a paso

Instala Django (con versión fija)

En vez de instalar Django a secas, fijamos la versión — así todas quedan exactamente igual, y este mismo archivo sirve después para el deploy.

  1. 1

    Con el entorno activado, crea un archivo requirements.txt en la carpeta del proyecto.

  2. 2

    Escribe adentro, tal cual: Django~=5.2.12

  3. 3

    Instala con: pip install -r requirements.txt

Terminal

Verifica que Django quedó instalado

Con el entorno todavía activado:

$django-admin --version
5.2.17
03

Tu primer proyecto

Acá empieza lo bueno

Paso a paso

Crea el proyecto

El punto final es clave: le dice a Django que trabaje en esta misma carpeta, no en una nueva.

  1. 1

    Con el entorno activado: django-admin.exe startproject mysite .

  2. 2

    Fíjate en el punto (.) al final — sin él, Django crea una carpeta extra que después complica todo.

  3. 3

    Explora lo que se creó: manage.py y una carpeta mysite/ con settings.py, urls.py y wsgi.py.

Si ves un error

"manage.py already exists"

Pasa si corres el comando dos veces en la misma carpeta — Django no sobrescribe archivos que ya existen, y con razón. Si te pasa: borra manage.py y la carpeta mysite/ que se creó, y corre el comando una sola vez.

Terminal

Crea la base de datos

Prepara las tablas que Django necesita para funcionar (usuarios, permisos, sesiones...).

$python manage.py migrate
Applying contenttypes.0001_initial... OK
Applying auth.0001_initial... OK
... (más migraciones) ...
Applying sessions.0001_initial... OK

Terminal

Enciende el servidor

$python manage.py runserver
Starting development server at http://127.0.0.1:8000/
Quit the server with CTRL-BREAK.

¡Listo!

Ya tienes un sitio Django corriendo.

Abre http://127.0.0.1:8000 en el navegador — si ves un cohete y el mensaje "The install worked successfully!", vas por buen camino. Lo próximo: ponerlo en internet.

Antes de los modelos: clases y objetos

La idea que hace que todo lo demás tenga sentido

El molde y la cosa

Una clase es un molde. Un objeto es lo que sale de ese molde.

Piensa en la Pokédex: describe qué es un Pokémon en general — que tiene nombre, tipo, y sabe atacar — sin ser ninguno en particular. Cada Pokémon que atrapas es distinto. Ese Pokémon concreto es el objeto.

Código

El molde en código

Así se ve la Pokédex escrita como clase en Python:

class Pokemon: def __init__(self, nombre, tipo): self.nombre = nombre self.tipo = tipo def atacar(self): print(f"{self.nombre} usa un ataque tipo {self.tipo}")

Código

El objeto, hecho con el molde

Cada vez que "creas" uno, obtienes un Pokémon distinto — mismo molde, valores propios:

pikachu = Pokemon("Pikachu", "Eléctrico") charmander = Pokemon("Charmander", "Fuego") pikachu.atacar() # Pikachu usa un ataque tipo Eléctrico

¿Por qué te importa esto?

Los modelos de Django son exactamente esto.

class Post(models.Model): es un molde. Cada entrada de tu blog que crees va a ser un objeto hecho con ese molde — con su propio título, texto y fecha.

La misma idea, otro nombre

De Pokémon a Django

🎮 Pokémon
  • Clase Pokemon — el molde
  • Atributos: nombre, tipo
  • Un Pikachu atrapado — el objeto
  • Método: atacar()
🐍 Django
  • Clase Post — el molde
  • Campos: title, text
  • Una entrada de tu blog — el objeto
  • Método: publish()
